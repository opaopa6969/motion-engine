# motion-engine の外部契約と設計判断

このリポジトリには従来 `spec/` はなく、README と設計書に契約が分散していた。ここでは、コードの転記ではなく、利用側が壊してはいけない境界と、その理由だけを固定する。

## 契約

- エンジンは three.js / VRM / DOM に依存しない。入力・出力は数値と plain data のみで、同じ入力から同じ Pose を返す。
- `MotionEngine.update(dt, ctx)` の Pose は、`MANAGED` のボーン名から Euler ラジアン `[x, y, z]` への対応と、常に存在する非ボーンの `root: { y, z, tilt, lookDown }` から成る。
- `root` は VRM のボーン検索に渡さない。ボーンを適用するホストはノードの有無を確認し、`root` はアバターのルート移動・傾き・表情を扱う層で解釈する。
- IK 系の `geo` と collider は、ホストが測定・変換した plain data を受け取る。エンジンが特定リグの階層やレンダラを推測してはならない。
- アクションは `engine.play(action)` の同一キューで合成される。加算的な演技と、手先を実座標へ置く IK の上書きを同じフレームに共存させる。

## 変えてはいけない設計判断

### renderer-free を維持する

VRM の適用をエンジン内に持ち込むと、依存・状態・テスト環境が増え、現在の headless 契約が壊れる。リグ固有の測定と Pose の適用はホストの責務とする。

### `root` は別キーにする

root の移動・傾きは骨回転ではなく、VRM のボーン名として扱えない。Pose に平坦な `root` キーを追加すれば、既存のボーン適用側は未知のノードとして無視でき、全身化を加算的にできる。`root` をボーンへ変換することはしない。

### IK は pole と plain data を受け取る

手先だけから肘を推測すると、掃引中に肘が裏返る。pole を明示して解剖学的な向きを安定させる。three.js の型を受け取らず、座標・Euler・クォータニオン配列で境界を保つ。

### root の意味はホストで決める

`y`/`z`/`tilt` の符号を scene 固有の座標系へ変換する責務や、`lookDown` を表情へ結び付ける責務はホスト側にある。エンジンは `Pose.root` に値を出すだけで、カメラ・表情・物理を直接操作しない。
